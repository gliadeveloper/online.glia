# 코칭·코스 미디어 보관 정책

- 작성: 2026-10-05 / 보관·복구 원칙 갱신: 2026-10-07
- 대상: 의사결정
- 범위: 코스 레슨과 코칭 콘텐츠에 넣는 이미지·영상·오디오
- 개발 정책: [보관 경로와 수명](./media-r2-folder-structure.md) · [자산 데이터](./media-asset-database-design.md)

## 결론

코스와 코칭의 미디어를 **문서에 붙는 첨부 파일**이 아니라 **보관함의 자산**으로 관리한다.

서비스가 제공하는 공통 자료와 코치·관리자가 올린 내 자료를 한 보관함에 두고, 코스와 코칭이 그 원본을 골라 쓴다. 쓸 때마다 파일을 복사하지 않는다. 보관함에서 자료를 지워도, 이미 그 파일을 쓰는 코스와 코칭은 그대로 재생된다.

이번 결정에 백업 버킷은 포함하지 않는다. 원본 전체의 재해 복구는 별도 판단이다.

## 지금 생기는 문제

코스와 코칭 편집기에서 이미지·영상·오디오를 넣으면, 그 파일이 곧장 저장소에 올라가고 본문에는 그 주소만 남는다. 파일 목록, 소유자, 보관 여부, 어느 수업에 쓰이는지는 기록되지 않는다.

그래서 같은 자료를 다시 쓰려면 다시 올려야 한다. 코스 A, 코스 B, 코칭 C에 같은 안내 오디오를 넣으면 파일이 세 개 생긴다. 코칭용 폴더와 코스용 폴더가 따로 있어, 한 자료를 양쪽 상품이 공유하는 구조가 아니다.

파일이 문서 밖으로 관리되지 않아 정리도 되지 않는다. 편집 중 넣었다가 저장하지 않은 파일, 본문에서 뺀 파일, 다음 수업에 쓰려고 미리 올린 파일이 같은 더미에 남는다. 반대로 본문에 주소만 남아 있고 실제 파일은 없는 경우도 있다.

2026-10-05 조사 기준 저장 파일은 151개, 8.19GB였다. 그중 당시 조사한 저장 콘텐츠에서 참조되지 않는 파일이 58개, 4.25GB였다. 이 미참조 합계에는 코스·코칭 외 수업자료·커뮤니티 파일도 포함된다. 이 수치는 당시 기준선이다. **본문에 없다**는 뜻이지 **지워도 된다**는 뜻이 아니다. 다음 수업용으로 둔 파일과, 업로드가 끊기고 남은 파일이 구분되지 않는다.

큰 영상은 앱 서버가 파일 전체를 받은 뒤 저장소로 다시 보낸다. 재생도 앱 서버를 지난다. 코스 영상은 200MB, 코칭 영상은 500MB까지다. 콘텐츠 편수가 늘면 업로드와 재생이 서비스 서버의 부하가 된다.

2026-10-05 조사에서는 외부 백업이 확인되지 않았다. 당시 완성 파일을 보관 의사와 사용처에 따라 정리하는 체계도 없었다. 현재 운영 수치는 배포 전 다시 확인한다.

## 이대로 두면 커지는 문제

우리가 파는 것은 계정이나 문서 칸이 아니라 수업 내용이다. 영상과 오디오가 깨지면 이미 결제한 코스와 이미 제공한 코칭이 깨진다.

제작이 늘수록 같은 자료의 복제본이 저장량을 끌어올린다. 안내 오디오 100MB를 코칭 100회에 각각 올리면 원본만 10GB다. 편당 업로드가 기본 공정이 되면 비용은 고유 자료의 양이 아니라 발행 횟수에 비례한다.

용량을 줄이려고 본문에 연결되지 않은 파일을 지우기 시작하면 사고가 된다. 조사에서 본 4.25GB 안에는 다음 수업용 원본이 섞여 있을 수 있다. 그 구분 없이 지우는 자동화는, 아직 발행 전인 자료를 먼저 없앤다.

코치가 자기 자료를 정리하는 일도 위험해진다. 목록에서 뺐다는 이유만으로 파일이 사라지면, 과거에 만들어 둔 레슨과 회원에게 발행한 코칭까지 재생이 끊긴다. 콘텐츠 사업에서 보관함 정리는 자주 있어야 하고, 이미 전달한 상품은 그 정리의 영향을 받으면 안 된다.

어떤 파일이 어느 상품에 쓰이는지 모르면, 파일 유실이 났을 때 영향 범위를 말할 수 없다. 회원에게 어느 회차가 깨졌는지, 무엇을 다시 올려야 하는지를 본문을 하나씩 열어 확인해야 한다.

개인이 올린 자료와 서비스 공통 자료의 경계도 없다. 코치의 음원을 코스에 넣었을 때 수강생은 그 수업만 들을 수 있어야 하고, 코치의 자료 목록 전체를 볼 수 있으면 안 된다. 현재도 경로에서 코스·회차를 찾아 열람 권한을 검사한다. 다만 보관함 소유권과 여러 콘텐츠의 사용처가 별도 기록되지 않아, 공통·개인 자료를 재사용할 때 필요한 권한을 일관되게 관리하기 어렵다.

## 콘텐츠 사업에서 이 방향이 맞는 이유

제작의 기본 단위는 문서가 아니라 재사용 가능한 자료다. 하나의 설명 영상, 하나의 안내 오디오, 하나의 도판을 여러 코스와 여러 코칭 회차에 배치한다. 보관함이 있고 콘텐츠가 그 자료를 가리키면, 배치가 늘어도 원본은 하나다. 100MB를 100곳에 써도 원본 용량은 100MB이고, 늘어나는 것은 사용 기록이다.

이미 만든 상품을 지키는 일과 자료를 정리하는 일은 따로여야 한다. 내 자료에서 삭제해도 그 파일을 쓰는 코스와 코칭은 유지된다. 휴지통에서 복원할 수 있고, 유예가 끝나 실제로 지워지는 것은 보관 의사도 없고 어디에도 쓰이지 않는 파일뿐이다. 다음 수업에 쓰려고 올려 둔 파일은 아직 본문에 없어도 정상 보관이다.

이 구분은 편집 도구에서 확인된 운영 방식과 같다. 제공 자료와 개인 업로드를 보관하고, 문서가 그 자료를 골라 쓰며, 보관함에서 지워도 이미 만든 결과물은 남긴다. 우리는 문서마다 사본을 떠서 남기는 방식이 아니라, 원본 하나를 여러 콘텐츠가 참조하는 방식으로 간다. 저장량을 발행 횟수가 아니라 고유 자료 기준으로 관리할 수 있다.

업로더에게 보여주는 저장 용량은 그 사람이 올린 원본의 할당량이다. 공통 자료, 미리보기용으로 만든 파일, 서버 백업 용량과 같은 숫자가 아니다. 휴지통에 있는 동안은 파일이 남아 있으므로 할당량에 포함된다.

## 결정한 정책

1. 공통 자료와 내 자료를 둔다. 코스와 코칭은 같은 보관함에서 고른다.
2. 한 자료를 여러 콘텐츠에 써도 원본 파일은 하나다.
3. 보관함에서 삭제해도 이미 사용 중인 코스·코칭은 재생된다. 새 콘텐츠에 다시 넣는 것만 막는다.
4. 휴지통은 복사용 폴더가 아니다. 상태만 바꾸고, 같은 파일을 복원한다. 기본 유예는 30일이다.
5. 본문에 없다는 이유만으로 삭제하지 않는다. 업로드가 중간에 끊긴 파일만 별도로 정리한다.
6. 이미 올라간 코칭·코스 파일은 옮기지 않는다. 새 업로드부터 공통/개인 구조를 쓴다.
7. 수강생은 자신이 열 수 있는 콘텐츠 안의 미디어만 재생한다. 업로더의 내 자료 목록은 보지 못한다.

이번에 하지 않는 것:

- 팀 단위 공유 드라이브
- 찜, 폴더
- 내 자료를 공통 자료로 승격
- 원본 전체를 담는 백업 버킷

공통 자료는 관리자가 등록한다. 코치는 공통 자료와 자신이 올린 자료를 자신이 편집하는 코스·코칭에 넣는다.

## 장애가 발생했을 때의 운영 원칙

사용 중인 콘텐츠 보호, 접근 권한, 검증된 파일만 제공하는 조건은 즉시 지킨다. 업로드·파일 저장·DB 기록은 서로 다른 작업이므로 서버가 중단되면 임시 파일이나 미완료 결과가 잠시 남을 수 있다. 이 파일은 보관함에 공개하지 않고, 작업 기록을 남겨 재시도와 주기적 대조로 정리한다.

임시 업로드는 같은 버킷의 별도 임시 영역에 두고 수명 규칙을 적용한다. 정상 완료 후에도 임시 파일을 정리한다. 사용 중인 최종 자산에는 기간 기반 삭제를 적용하지 않는다. 이는 백업 구조가 아니다.

삭제 완료 표시는 서비스에서 다시 제공하지 않는다는 결정과 확인 당시 파일 정리를 뜻한다. 삭제 이력은 유지하여 늦게 도착한 잔여 파일도 다시 찾는다. 사용자에게 표시하는 용량과 실제 저장소의 잔여 바이트는 별도로 관리한다.

개발 완료의 판단은 정상 동작뿐 아니라 서버 중단·재시도·동시 편집·부분 삭제 시험을 포함한다. 저장소 장애로 정리가 지연되면 성공으로 숨기지 않고 운영 알림과 잔여 용량으로 표시한다.
