# 코치 포털 — 코칭권 기능

> **무엇:** 코치가 **코칭권**을 운영할 때 하는 일과, 그 일이 붙는 화면·도메인.  
> **왜:** Q&A 경로를 손대기 전에, 발행·현황·답변을 한 사이클로 고정한다.  
> **상태:** implemented (코치 운영 보드 v1)  
> **허브:** [policies.md](./policies.md) §6 · §7  
> **회원 화면:** [screens/coaching-list.md](./screens/coaching-list.md) · [screens/coaching-session.md](./screens/coaching-session.md)

---

## 0. 한 줄

코치의 코칭권 일은 **`scheduledAt` 날짜 기준으로 그날 열 페이지를 쓰고**, **무엇이 열렸는지 보고**, **열린 페이지의 질문에 답하는 것**이다.

Shop 상품 만들기, LMS 레슨, 라이브, 주문 승인은 이 문서 밖이다.

---

## 1. 용어

코치가 말하는 말과 코드 객체가 다르다. UI 카피·IA는 **코치가 쓰는 말**을 우선한다.

| 코치가 말하는 말 | 도메인 | 회원이 보는 곳 |
|------------------|--------|----------------|
| 코칭 상품 / 오퍼링 | `CoachingOffering` + 회차 템플릿 | Shop에서 사는 구성. 코칭 탭의 “상품명” |
| 코칭권 | `CoachingEntitlement` | `/coaching` 카드 1장 = 코칭권 1건 |
| **코칭 페이지** / 회차 | `CoachingSession` | `/coaching/sessions/[id]` — 코치가 쓰고 발행하는 본문 |
| **발행일** | `scheduledAt` | 회차 카드 「N월 N일 오픈됩니다」. 코치 보드의 날짜 축 |
| **실제 발행 시각** | `publishedAt` | 회원에게 안 보임. 코치가 연 결과 |
| 한줄 기록 | `CoachingSessionLog` | 발행된 페이지. 과제 후 일기. **답변·알림 없음** |
| Q&A | `CoachingSessionConversation` + `CoachingSessionMessage` | 발행된 페이지 하단 댓글형 대화 |

**코칭 페이지** = 특정 회원 · 특정 코칭권 · N회차에 붙는 문서. 오퍼링 전체가 아니라 **이미 부여된 코칭권의 회차 한 장**이다.

```
오퍼링 (팔 상품, 회차 뼈대, 회차별 발행 오프셋)
  └─ 코칭권 (회원 A에게 부여된 이용권)
       └─ 코칭 페이지 × N (1회차…N회차, 회원만의 사본)
            ├─ scheduledAt = 이날 연다 (계획)
            ├─ 한줄 기록 (회원 일기, 코치 열람만)
            └─ Q&A (그 페이지가 발행된 뒤에만)
```

부여 시 회차 껍데기(`EMPTY`)와 빈 대화방이 만들어진다. 본문은 코치가 회원마다 쓴다.

## 2. 날짜 — 소프트 vs 하드

같은 회차에 날짜가 두 개다. **발행 보드는 소프트를 축으로 한다. 버튼은 하드만 본다.**

| | 소프트 `scheduledAt` | 하드 `publishedAt` + `publicationStatus` |
|--|----------------------|------------------------------------------|
| 의미 | 이날 이 회차를 연다 (계획) | 이때 열렸다 / 열렸는가 (결과) |
| 채워지는 때 | 코칭권 부여. `validFrom + scheduledOffsetDays` | 코치가 「회원에게 발행」을 누른 순간 |
| 코치 UI | **날짜별 할 일.** 오늘 · 밀림 · 예정 | 행의 상태: 미작성 / 초안 / 발행됨 |
| 회원 UI | 미발행이면 「N월 N일 오픈됩니다」 | `PUBLISHED`만 본문·Q&A |
| 막지 않는 것 | 그날 전·후 발행 모두 허용 | — |

**불변:** 발행 버튼을 `scheduledAt`으로 비활성화하지 않는다. 미리 써 두거나, 밀린 걸 나중에 열 수 있다. 보드가 알려 줄 뿐 잠그지 않는다.

이 축이 없으면 5명 × 5회 = 미발행 25장이 한 리스트가 된다. 날짜로 자르면 코치는 **오늘 열 것만** 본다.

지금 값은 거의 다 **코칭권 시작일 = 결제일**이다. 코치 오퍼링은 `scheduledOffsetDays = 0`이라 부여 시 1~N회차가 같은 날로 저장된다. (시드처럼 오프셋이 있는 오퍼링만 회차가 벌어진다.)

v1 전제: **코치가 회차 `scheduledAt`을 수정한다.** 이미 쌓인 결제일 데이터를 회차마다 나눠 쓰면 보드가 살아난다. 오퍼링 오프셋은 나중(신규 부여 기본값)이다.

## 3. 코치 과업

우선순위는 **빈도 × 실패 비용**이다. 아래 1~4가 코칭 메뉴의 본체다.

### 3.1 핵심 루프 (매일~매주)

| # | 과업 | 코치가 묻는 말 | 완료 조건 |
|---|------|----------------|-----------|
| **1. 발행** | 그날 예정인 페이지를 써서 연다 | “오늘 열 회차 있지?” | `PUBLISHED`, 본문 있음. 날짜와 무관하게 버튼은 항상 가능 |
| **2. 수정** | 이미 연 페이지를 고친다 | “오타 / 영상 다시” | 같은 페이지 재저장. 회원은 최신 본문 |
| **3. 발행 현황** | `scheduledAt` 날짜로 무엇을 열지·열었는지 | “오늘 / 밀린 거 / 다음 주” | 날짜 그룹 + 미작성·초안·발행됨. 전 회차 플랫 덤프 아님 |
| **4. 미답 Q&A** | 열린 페이지의 질문에 답한다 | “누가 물어봤는데 내가 안 봤나?” | `awaitingReply = true` 가 0 |

1·2는 **문서 작업**(에디터). 3·4는 **운영 현황**(목록). 성격이 다르다. 한 화면에 섞이되, **서로 길을 막으면 안 된다.**

### 3.2 설정·예외 (가끔)

| # | 과업 | 언제 |
|---|------|------|
| **5. 오퍼링** | 상품명·회차 수·회차 제목 | 프로그램 처음. 회차 오프셋은 v2 |
| **6. 코칭권 부여** | 특정 회원에게 이용권 | 주문 외 수동 지급. 결제 플로우는 주문 메뉴 |
| **7. 회원 맥락** | 이 사람 코칭권·회차·질문 | 고객 상세에서 보조. 매일의 발행/답변 진입점은 아님 |

### 3.3 이 문서에 넣지 않는 일

| 일 | 메뉴 |
|----|------|
| Shop에 코칭 상품 올리기 | 상품 |
| 신청·결제 승인 | 주문 / 고객 |
| VOD·텍스트 레슨 | 코스 |
| Zoom 라이브 | 라이브 |
| 데일리 체크인 열람 | 체크인 |

## 4. 두 과업은 분리한다

Q&A를 가깝게 만들다가 **발행이 느려지면 실패**다. 반대도 실패다. 발행 보드를 날짜로 잘라도, 에디터 자리는 그대로다.

| | 발행·수정 | 미답 Q&A |
|--|-----------|----------|
| 코치 모드 | 한 회원 한 회차에 집중, 길게 씀 | 여러 회원 질문을 짧게 비움 |
| 산출 | 발행된 코칭 페이지 | 답한 메시지 |
| 좋은 UI | 오늘 날짜 묶음 → 에디터·임시저장·발행 1 hop | 미답 목록 → 그 스레드 답변 1 hop |
| 나쁜 UI | 미발행 전체 25장을 한 리스트 | 회차를 찾아 본문을 지나야 질문 |

**제약 (이후 UI 변경 시 불변):**

1. 코칭 페이지 작성·임시저장·발행은 세션 상세의 **주 과업**으로 남긴다.
2. 발행 버튼·에디터는 Q&A 인박스 뒤로 밀리지 않는다.
3. **발행 버튼을 `scheduledAt`로 막지 않는다.** (소프트 일정)
4. 미답 확인은 세션 본문을 열지 않고도 가능해야 한다.
5. 발행 할 일은 **날짜 그룹**으로 보인다. 미발행 전체를 한 줄로 쌓지 않는다.

회원 쪽 규칙은 유지한다: **발행된 페이지만** 본문·Q&A가 보인다. 코치도 미발행 회차에는 답할 수 없다. 날짜가 되어도 미발행이면 회원은 「아직 등록된 코칭이 없습니다」.

## 5. 상태

### 코칭 페이지 (`CoachingSessionPublicationStatus`)

| 값 | 의미 | 회원 | 코치 |
|----|------|------|------|
| `EMPTY` | 껍데기만. 본문 없음 | 회차 목록에만, 비활성 | 써야 하는 페이지 |
| `DRAFT` | 저장됨, 아직 안 연 상태 | 안 보임 | 이어서 쓰고 발행 |
| **PUBLISHED** | 회원에게 열림 | 본문 + 한줄 기록/Q&A 스위치 | 수정 가능, Q&A·기록 열람 |

목록 카피는 상태값 대신 **미작성 / 초안 / 발행됨**을 쓴다.

### 날짜로 본 발행 일감 (소프트)

미발행(`EMPTY` \| `DRAFT`)만 보드에 올린다. 기준은 `scheduledAt`의 **날짜**(Asia/Seoul).

| 버킷 | 조건 | 코치에게 |
|------|------|----------|
| **밀림** | 날짜 < 오늘 | 이미 지났는데 안 연 것. 맨 위 |
| **오늘** | 날짜 = 오늘 | 오늘 열 것 |
| **예정** | 날짜 > 오늘 | 접어 두고, 날짜 헤더로만 |

`PUBLISHED`는 이 일감에서 빠진다. “이미 연 것”은 코칭권 보드·세션 상세에서 본다.

### 코칭권 (`CoachingEntitlementStatus`)

`ACTIVE` · `EXPIRED` · `COMPLETED` · `SUSPENDED` · `REVOKED`  
진행 표시: `{completedSessions}/{totalSessions}` + `validUntil`.

### Q&A

| 조건 | 의미 |
|------|------|
| 페이지 `PUBLISHED` 아님 | 질문·답변 불가 |
| 회원 메시지 `awaitingReply = true` | 미답 |
| 코치가 답변 | 해당 미답 해제, 회원에게 알림 |

대화는 지금 **회차(페이지) 단위**다. 코치는 코칭권·회원 단위로 묶어서 **보고 싶어 한다.** 저장 단위를 당장 바꿀 필요는 없다. 목록만 코칭권/회원으로 모아도 과업 4는 성립한다.

### 한줄 기록 (`CoachingSessionLog`)

과제 후 회원이 남기는 일기. **Q&A가 아니다.**

| | |
|-|-|
| 작성 | 회원만. 발행된 회차. N개 (120자, 회차당 50) |
| 코치 | 세션 상세 「한줄 기록」 탭에서 읽기만 |
| 답변 | 없음. 미답 인박스에 올리지 않음 |
| 알림 | 없음 |

## 7. 화면이 답해야 하는 질문

이후 IA·카피는 이 네 줄에 답하면 된다.

1. **오늘(`scheduledAt` = 오늘) 열 페이지는 무엇인가? 밀린 것은?**
2. **이미 연 페이지는 누구의 몇 회차인가?**
3. **이 코칭권은 몇 장이나 열렸나?** (예: 김민지 · 2/8 발행)
4. **열린 페이지 중 미답 질문이 있는가?** (회원·코칭권·회차·미리보기)

1~3을 희생하고 4만 올리지 않는다. 1의 답이 “미발행 25장”이면 실패한 화면이다.

## 8. IA 방향 (미구현)

화면 스펙이 아니라 **과업이 앉을 자리**만 적는다. 확정 후 `docs/screens/coach/`에 URL 단위로 푼다.

### 코칭 홈 (`/coach/coaching`) — 운영 보드

두 개의 일감이 **같은 위계**로 보인다.

| 보드 | 과업 | 묶는 축 | 행 한 줄 |
|------|------|---------|----------|
| 발행 | 1, 3 | `scheduledAt` 날짜 (밀림 / 오늘 / 예정) | 회원 · 코칭권 · N회차 · 미작성/초안 |
| 미답 Q&A | 4 | 최신 미답 | 회원 · 코칭권 · N회차 · 질문 미리보기 · 대기 시간 |

발행 보드 예:

```
밀림
  9/7  김민지 · 8주 챌린지 · 2회차 · 초안
  9/7  박서준 · 8주 챌린지 · 2회차 · 미작성

오늘  9/14
  김민지 · 8주 챌린지 · 3회차 · 미작성
  이하늘 · 8주 챌린지 · 1회차 · 초안

예정
  9/21  (3)
  9/28  (5)
```

- 밀림·오늘만 기본으로 펼친다. 예정은 날짜 헤더 + 건수. 펼치면 그때 행이 나온다.
- 행 클릭 → 세션 상세 **에디터**(과업 1·2). 날짜가 남았어도 발행 가능.
- 미답 클릭 → 같은 세션의 **Q&A**. 에디터를 읽게 만들지 않음.
- 코칭권 이름 클릭 → 그 이용권의 회차 보드(아래).
- 사이드바 「코칭」 뱃지는 미답 수. 밀린 발행 건수는 보드 헤더에.

5명 × 5회여도 오늘은 “그날 `scheduledAt`인 행”만 보인다. 25장을 한 번에 깔지 않는다.

### 코칭권 보드 (신규에 가깝다)

한 회원 + 한 오퍼링의 회차 N장. 여기는 날짜가 아니라 **회차 순서**다. “이 사람 프로그램이 어디까지 열렸나.”

| 회차 | 발행일 (`scheduledAt`) | 페이지 상태 | Q&A |
|------|------------------------|-------------|-----|
| 1 | 8/31 | 발행됨 | 미답 1 |
| 2 | 9/7 (수정 가능) | 초안 (밀림) | — |
| 3 | 9/14 (수정 가능) | 미작성 (오늘) | — |

### 세션 상세 — 발행 워크벤치

과업 1·2의 집. 바꾸지 말 것: 에디터, 임시저장, 회원에게 발행, 발행됨 표시. **날짜가 아니라고 버튼을 비활성하지 않음.**

바꿀 것:

- 상단에 **발행 상태** · **발행일(`scheduledAt`, 코치가 수정)** · **미답 N**
- 밀림이면 “발행일 지남” 힌트만. 잠금 아님
- Q&A는 같은 페이지에 두되, **탭이거나 에디터와 동등한 섹션**. 스크롤 맨 아래 금지
- 미답 보드에서 오면 Q&A가 바로 보임. 발행 보드에서 오면 에디터가 바로 보임
- 뒤로: 코칭 허브(날짜 보드) 또는 그 코칭권 보드

**발행일은 코치가 고친다.** Admin이 이미 가진 datetime 필드를 코치 세션 PATCH에도 연다. 바꾸면 회원 「N월 N일 오픈됩니다」와 날짜 보드가 같이 움직인다.

한 사람 5회를 세션마다 열면 번거롭다. **코칭권 보드에서 회차 N개의 발행일을 한 번에** 고치는 쪽이 본 편집면이다. 세션 상세는 단건 보정.

### 오퍼링 오프셋 — v2

신규 부여 때 날짜가 자동으로 벌어지게 하려면 템플릿 오프셋이 필요하다. v1은 코치가 이미 생긴 회차 날짜를 고치는 것으로 충분하다. 오프셋 기본값(`0, 7, 14, …`)은 그다음이다.

## 10. 미결

화면 스펙으로 넘기기 전에 정할 것.

| # | 항목 | 기본 안 |
|---|------|---------|
| 1 | 코칭 홈 기본 탭 | 밀림+오늘 발행이 있으면 발행 보드, 없으면 미답. 둘 다 0이면 코칭권 목록 |
| 2 | 코칭권 보드 URL | `/coach/coaching/entitlements/[id]` 신규 vs 고객 상세 확장 |
| 3 | Q&A 저장 단위 | v1은 회차 스레드 유지, 목록만 코칭권으로 그룹 |
| 4 | 발행 후 수정 = 재발행? | 지금은 PATCH로 본문만 갱신, 별도 재발행 없음. 유지 |
| 5 | 미발행 회차에 코치가 먼저 쓸 수 있나 | 아니요. 회원 Q&A는 PUBLISHED만 |
| 6 | 오퍼링 오프셋 기본값 | **v2.** v1은 코치가 회차 `scheduledAt`을 직접 수정 |
| 7 | 기존 데이터 (날짜 = 결제일) | 마이그레이션 없음. 코치가 회차·코칭권 보드에서 날짜를 나눔 |
| 8 | 코치 `scheduledAt` 수정 | **v1 예.** 코칭권 보드에서 N회 일괄 + 세션 상세 단건. 발행 여부와 무관하게 수정 가능 |

날짜 보드(§2 · §8), 버튼 잠그지 않음, 코치 날짜 수정(§8)은 미결이 아니다.
